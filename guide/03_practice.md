# 03. 실습

## 실습 1: 프로젝트 감사

목표는 실행 전에 문서와 의존성, 환경 변수 표본을 확인하는 습관을 만드는 것이다.

```bash
python examples/01_project_audit.py ../ai_agents/agentic_rag_system
```

코드는 파일의 존재 여부만 검사한다. 다음 단계로 README의 설치 명령과 실제 파일명이 일치하는지, `.env.example`에 의심스러운 실제 키가 없는지 검사해 본다.

## 실습 2: 최소 로컬 RAG

```bash
python examples/02_local_rag.py
```

이 예제는 문서를 단어 집합으로 표현하고 질문과 겹치는 단어 수로 순위를 매긴다. 실제 임베딩 검색보다 단순하지만 검색 결과와 답변을 분리해 관찰할 수 있다.

확장 순서:

1. 불용어를 제거하고 형태를 정규화한다.
2. 단순 겹침 점수를 TF-IDF 또는 BM25로 바꾼다.
3. 문서를 문단 단위로 청킹하고 문서 ID와 위치를 보존한다.
4. 검색 결과가 없으면 답변을 거부하도록 한다.
5. 생성 모델을 연결하되 인용 ID가 검색 결과에 실제 존재하는지 검증한다.

## 실습 3: 경계가 있는 도구 에이전트

```bash
python examples/03_bounded_agent.py
```

에이전트는 `lookup`과 `calculate`만 호출할 수 있고 최대 단계 수가 정해져 있다. 알 수 없는 도구와 잘못된 인자는 실행 전에 거부한다.

확장 순서:

1. 도구 인자를 dataclass 또는 JSON Schema로 검증한다.
2. 네트워크 도메인과 파일 경로 허용 목록을 추가한다.
3. 외부 부작용이 있는 도구에 승인 상태를 추가한다.
4. 각 행동, 지연 시간과 결과를 구조화 로그로 남긴다.
5. 무한 반복, 같은 호출 반복과 비용 한도를 검사한다.

## 실제 프로젝트 분석 과제

관심 있는 하위 프로젝트 하나를 골라 다음 표를 작성한다.

| 항목 | 확인 내용 |
| --- | --- |
| 사용자 가치 | 누구의 어떤 문제를 해결하는가? |
| 입력/출력 | 형식, 크기, schema는 무엇인가? |
| 모델 | 공급자, 모델명과 대체 가능성은? |
| 검색/도구 | 어떤 외부 데이터와 권한을 사용하는가? |
| 상태 | 메모리와 대화가 어디에 저장되는가? |
| 실패 처리 | timeout, rate limit, 빈 검색을 어떻게 처리하는가? |
| 평가 | 정확성, 근거성, 비용과 지연을 어떻게 측정하는가? |
| 보안 | 비밀값, 개인 정보와 prompt injection 경계는? |

그 뒤 한 가지 실패 사례를 테스트로 고정하고 개선 전후를 비교한다.
